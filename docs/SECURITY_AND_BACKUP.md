## 데이터 백업 도구

`scripts/database-backup.cjs`는 운영자용 CLI이며 웹이나 관리자 메뉴에 다른 회원의 자료를 내려받는 기능을 만들지 않습니다. MongoDB Database Tools의 `mongodump`가 설치된 신뢰할 수 있는 장비에서 기존 `MONGODB_URI`를 환경 설정으로 읽습니다. 비밀값을 명령 인자나 코드·Git에 넣지 않습니다.

별도 비밀번호 `PORTFOLIV_BACKUP_PASSWORD`(20자 이상)를 안전한 환경 설정으로 제공하고 다음을 실행합니다. 로그인 비밀번호와 다른 긴 무작위 비밀번호를 사용하고, 채팅·공개 저장소에 입력하지 마세요.

```sh
npm run backup:database -- /안전한/개인/경로/portfoliv-data.enc
node scripts/database-backup.cjs decrypt /안전한/개인/경로/portfoliv-data.enc /안전한/개인/경로/restore.archive.gz
```

선택된 데이터베이스 전체와 GridFS를 `mongodump --archive --gzip`으로 읽어 AES-256-GCM으로 바로 암호화합니다. 암호화 키는 무작위 salt와 scrypt로 도출하고, 헤더까지 무결성을 검사합니다. 기존 파일은 덮어쓰지 않습니다. MongoDB URI가 담긴 임시 설정은 0600으로 만들고 종료 시 제거합니다. 파일 변조나 잘못된 비밀번호로 복호화하면 불완전한 출력은 삭제합니다. 비밀번호 분실 시 복구할 수 없습니다.

백업 성공 후 반드시 개인 저장소로 복사하고, 별도의 시험용 MongoDB에 `mongorestore --archive=... --gzip`로 복원해 컬렉션·첨부 수와 열람을 확인하세요. 운영 DB에 자동 복원하거나 `--drop`을 실행하지 않습니다. 이 도구는 일반 논리 백업이므로 여러 컬렉션에 대한 시점 일치가 자동 보장되지 않습니다. 데이터 변경 테스트 전에는 쓰기를 멈춘 상태에서 백업하거나 Atlas의 일관된 스냅샷 기능을 사용해야 합니다.

## 적용한 보안

- Helmet, CSP, 클릭재킹 차단, MIME 추측 방지, no-referrer, 민감 기기 권한 차단, 운영 HTTPS HSTS. rich text 서식에 필요한 인라인 CSS만 허용하고 인라인 스크립트·이벤트·객체 실행을 차단합니다. 기존 Google 글꼴과 YouTube/Vimeo 영상은 유지합니다.
- Render의 한 단계 프록시만 신뢰합니다. 개발 서버에서는 전달된 IP를 신뢰하지 않습니다. 로그인 제한 저장소를 상한과 주기적 정리가 있는 구조로 바꾸고 `Retry-After`를 제공합니다.
- 상태 변경 요청의 Origin을 프로토콜까지 검증하고, cross-site Fetch Metadata 요청을 거절합니다. API 응답은 개인용 no-store입니다.
- 새 비밀번호는 scrypt `N=65536, r=8, p=2`로 저장합니다. 기존 해시는 계속 검증하고 정상 로그인 시 더 강한 설정으로 갱신합니다. 비밀번호 처리 동시 작업을 제한해 무료 서비스 메모리를 보호합니다.
- 일반 API에서 URL의 탭 인증값을 받지 않습니다. GET/HEAD의 본인 미디어 URL에서만 기존 호환성을 유지합니다. 세션 쿠키는 Render에서도 Secure·HttpOnly·SameSite=Strict입니다.
- Multer 2 최신 수정 버전, 유지되는 라이브러리 기반 HTML 정화, 불필요한 uuid 의존성 제거. 악성 URL·이벤트·외부 미디어 삽입을 막고 기존 글꼴·글자 크기·굵기·색상은 유지합니다.
- 업로드 MIME을 사용자 입력만 믿지 않고 파일 헤더로 확인합니다. 확인되지 않은 파일은 다운로드 전용으로 처리합니다. 파일당 50MB·한 번 10개 제한을 유지하면서 multipart 필드·부분 수와 업로드 동시 작업도 제한합니다.
- 잘못된 JSON·입력 타입은 400, 용량 초과는 413으로 처리하며 내부 오류 정보를 응답에 노출하지 않습니다.

## 본인만 설정하는 2단계 인증

`마이페이지 → 내 계정 정보 → 2단계 인증`에서 현재 비밀번호를 확인한 뒤 인증 앱 QR/설정 키를 등록하고 6자리 코드를 확인합니다. 관리자도 기존 관리자 비밀번호로 같은 과정을 진행합니다. 다른 회원을 지정하는 입력이나 관리자가 다른 회원의 인증 키를 보는 기능은 없습니다.

**사용자가 앱 등록과 코드 확인을 완료해야 실제로 켜집니다. 배포만으로 본인 계정에 활성화되지 않습니다.** 일반 회원에게 강제로 적용하거나 신규 가입을 제한하지 않습니다.

- 10분 동안 유효한 설정을 현재 세션에만 묶습니다. 동일 계정의 주기적인 로그인 상태 확인은 설정 QR·한 번만 표시되는 복구 코드를 지우지 않습니다. 로그아웃·계정 전환·해당 화면 이동 시 화면에서 제거합니다.
- 인증 비밀키는 `PORTFOLIO_MFA_SECRET`으로 AES-256-GCM 암호화하고 사용자 ID에 묶습니다. 별도의 무작위 암호화 키를 추가하고 기존 MongoDB·관리자 비밀번호·ADMIN_SESSION_SECRET 값은 보존합니다. 별도 키가 없으면 기존 ADMIN_SESSION_SECRET(32자 이상)을 사용할 수 있습니다. 설정이 없으면 UI에서 준비가 필요하다고 안내하며 기존 로그인은 유지됩니다. 활성화 후에는 해당 비밀값을 반드시 별도로 안전하게 보존해야 합니다. 키 교체 절차 없이 바꾸면 인증 앱 코드 확인을 할 수 없게 됩니다.
- 같은 인증 코드는 원자적으로 한 번만 사용됩니다. 복구 코드는 고엔트로피 무작위 값 10개이며 한 번만 표시하고 해시만 저장합니다. 각 코드는 1회용입니다. 앱을 잃어버리면 로그인 화면에 미사용 복구 코드를 입력합니다.
- 켜기·해제 시 다른 기기의 기존 세션을 무효화합니다. 해제에도 비밀번호와 인증 코드 또는 미사용 복구 코드가 필요합니다.
- Render/GitHub 계정 자체의 2단계 인증은 각 서비스의 계정 보안 설정에서 본인이 등록해야 합니다. 사이트의 인증 앱 기능이 그 계정 설정을 대신하지 않습니다.

## 검증

실제 MongoDB나 운영 회원을 수정하지 않는 메모리 모델·로컬 HTTP 서버로 검증합니다.

```sh
node test-security.cjs
node test-private.cjs
node test-career.cjs
# 별도 터미널에서 실행
node test-security.cjs --serve
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium node test-security-browser.cjs
node test-career.cjs --serve
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium node test-career-browser.cjs
npm audit
```

보안 HTTP 검사는 CSRF·IP 위장·JSON 한도·입력 타입·XSS·파일 헤더·회원/관리자 인증 앱·재사용 경쟁·복구 코드·세션 무효화·이전 비밀번호 해시 갱신을 포함합니다. 백업 암호화·복호화·변조 검사는 가짜 mongodump의 시험 자료로 진행하며 운영 데이터 백업이나 실제 DB 복원 검사로 간주하지 않습니다. 브라우저는 PC 1440px와 모바일 390px에서 회원가입부터 인증 앱 설정·해제와 CSP 실행 차단을 확인하고 기존 PDF·편집·복제·미리보기도 검증합니다.

보고된 의존성 취약점 0건은 npm audit 실행 시점의 결과입니다. 운영 상태와 코드 변경에 따라 다시 점검해야 하며 모든 해킹·보안 테스트의 통과를 보장하지 않습니다.
