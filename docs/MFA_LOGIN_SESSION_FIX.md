# 로그인 재시도와 2단계 인증 — 2026-10-12

사용자는 복구 코드까지 발급된 등록 완료 계정이 로그아웃 뒤 비밀번호만으로 로그인된다고 보고했습니다. 운영 계정의 실제 DB 상태나 비밀번호를 조회하지 않았으며 해당 계정의 원인까지 확정한 것은 아닙니다.

기존 배포 커밋 4532a6e를 별도 로컬 메모리 서버로 실행해, 등록 완료된 기존 인증 세션을 가진 채 코드 없이 새 로그인을 요청하면 로그인 요청은 401이지만 기존 쿠키의 `/api/auth/session`은 여전히 authenticated:true인 경로를 재현했습니다. 따라서 로그인 화면의 오류 응답만 확인하는 검사는 충분하지 않았습니다.

- 관리자·일반 회원의 새 로그인 요청은 이전 쿠키의 서버 세션을 삭제하고 쿠키를 만료시킵니다. 코드가 없거나 잘못되면 기존 인증 상태로 돌아갈 수 없습니다.
- 실제 인증 코드/미사용 복구 코드 소비 성공은 서버 내부 WeakSet 증거로 구분합니다. 등록 표시만으로 인증 완료 세션을 만들지 않습니다.
- 등록 계정은 새 정책 버전 2가 기록된 인증 세션만 허용합니다. 이전 방식의 인증 완료 표시만 가진 세션은 배포 후 다시 인증해야 합니다. 미등록 계정의 세션은 이 정책으로 종료하지 않습니다.
- 세션 발급 직전에 저장된 등록 상태와 authVersion을 다시 확인합니다. 등록 상태 변경이나 증거 누락은 실패 처리합니다.
- 브라우저의 진행 중인 로그인과 이전 세션 조회 응답을 분리하여 오래된 응답이 실패 화면을 로그인 상태로 되돌리지 않도록 합니다.
- 등록 계정은 코드가 필수라는 문구를 명확히 했으며 미등록 계정은 기존 비밀번호 로그인을 유지합니다. 서버 코드에서 등록 판단 기준은 저장된 등록 표시 또는 암호화 키이고 관리자와 회원이 동일합니다.
