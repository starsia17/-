# 포트폴리브 1.0.1 — 요청 폭주 대응 보강

2026-10-12. 기존 API 중심 제한에 전체 경로의 자원 보호를 추가합니다. Node/Express 단일 인스턴스 안에서 처리량과 대기를 제한하는 패치이며 네트워크 대역폭이나 플랫폼 용량을 초과하는 모든 DDoS를 막는 보장이 아닙니다.

## 적용 내용

- 정적 파일·없는 주소를 포함한 전체 요청: 순간 허용 300개, 초당 150개 보충의 단조 시간 기반 token bucket. 처리 중 요청 128개 상한. JSON 파싱과 파일/DB 접근 전에 적용.
- API: 순간 허용 120개, 초당 60개 보충. 기존 IP당 분당 600회 제한 유지. 전체 동시 처리 40개, IP별 24개. 초과는 429/503과 재시도 대기시간으로 응답. 완료/중단 시 슬롯을 반환하고 IP 항목을 제거.
- 전역 제한을 IP별 기록보다 먼저 적용. 버킷 저장소 상한과 만료 정리를 적용하여 IP가 계속 달라져도 기록을 무한 생성하지 않음.
- JSON 요청: 기존 요청당 4MB를 유지하며 동시에 예약되는 원문 바이트를 16MB로 제한. 길이가 없는 chunked JSON은 요청당 최대값을 예약. 초과·잘못된 크기는 파싱 전에 거절. multipart 파일 업로드는 이 JSON 예산으로 막지 않음.
- `/api/health` GET은 별도의 초당 20회/IP당 분당 60회 예산으로 처리. 일반 API/파일 요청의 슬롯 고갈에 휘말리지 않도록 파서·정적 파일·휴지통 DB 처리 전에 응답. 본문을 붙인 상태 확인 요청은 거절.
- 비활동 소켓 45초 종료. 인증과 기존 업로드 슬롯 검사까지 통과한 multipart 업로드만 기존 300초 대기를 유지. 기존 파일당 50MB/10개, 전체 업로드 3개·계정별 1개, KDF 동시 계산 3개 제한은 유지.
- 클라이언트가 다운로드를 중단하면 GridFS 다운로드 스트림도 종료하여 불필요한 DB 읽기를 중단.
- package와 운영 health 버전을 1.0.1로 일치시킴. MongoDB URI·인증 키·관리자 비밀번호·기존 DB 데이터를 바꾸지 않음.

## 검증과 한계

`test-ddos.cjs`: 시간 경계의 버킷 보충, 순간 초과 차단, 저장소 만료/상한, IP별 동시 처리 분리, 완료/중단의 중복 반환 방지, JSON 예산/크기/중단 반환, 로컬 HTTP 24개 대기 요청 뒤 초과 거절, 상태 확인 별도 응답과 정상 처리 복귀를 검사합니다. 운영 서버에는 대량 요청이나 공격을 보내지 않습니다.

기존 security/private/career/MongoDB 정책과 PC 1440px·모바일 390px의 MFA, 프로필/PDF/복제/공유, 외부 동영상 위치 기능을 검사합니다. 로컬 테스트 계정만 사용합니다. 구형 계정 MFA 등록 저장 수정도 유지합니다.

Render 무료 단일 인스턴스를 유지합니다. Cloudflare/WAF 관리 연결 검색에서 사용할 도구가 없었고 외부 보호나 유료 확장 설정을 새로 적용하지 않았습니다. 앞단 네트워크 보호, 호스팅 처리 용량 및 운영 대응은 별도 영역입니다. 모든 공격에 대한 절대 무중단을 주장하지 않습니다.
