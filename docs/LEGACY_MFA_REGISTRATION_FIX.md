# 구형 계정 인증 등록 저장 실패 — 2026-10-12

운영 앱 로그에서 관리자 비밀번호 로그인에 registered:false가 기록됐습니다. 이어서 해당 서버의 관리자 원본 문서 필드 존재 여부를 확인한 결과 인증 관련 필드가 없었습니다. 값을 출력하지 않고 필드 이름·타입·존재 여부만 점검했습니다.

구형 계정의 authVersion 필드가 DB에 없으면 Mongoose 문서에서는 기본값 0으로 보입니다. 기존 MFA 등록/해제/코드 소비 쿼리는 authVersion:0의 실제 저장 값만 일치시켜, 필드가 없는 계정은 등록 확인 시 HTTP 409가 됩니다. 관리자가 구형 계정이고 원본 인증 필드가 없는 운영 증거는 확인했으나 운영 계정의 과거 등록 시도를 직접 재현하지는 않았습니다.

메모리 시험 사용자·관리자에서 authVersion 필드를 삭제한 뒤 기존 코드의 등록 저장 409를 재현했습니다. 수정한 MFA 원자적 쿼리는 버전 0 또는 필드 부재를 동일한 초기 버전으로 비교하고, 버전이 증가한 계정은 이전과 같이 정확한 버전을 비교합니다. 등록 시 $inc가 새 버전 1을 저장하며 저장 결과를 다시 읽어 확인합니다. 기존 사용자·게시물·비밀번호·인증 키를 덮어쓰거나 관리자에게 다른 사용자 자료를 보여주지 않습니다.

반복 검사에서 별도로 발견된 테스트 오류도 수정했습니다. 등록 때 사용한 OTP 대신 나중에 새로 생성한 OTP를 재사용 검사에 넣던 테스트는 30초 경계를 넘으면 새 유효 코드가 되어 200이 나왔습니다. 등록 시 실제 사용한 동일 코드를 보관해 재사용 차단을 검사합니다. 새 유효 코드로 정상 로그인되는 동작을 버그로 처리하지 않습니다.

사용자 요청에 따라 security/private/career/MongoDB 정책 검사를 100회 반복 실행합니다. 결과와 매 회 로그는 `/workspace/portfoliv-verification-100/final-run/`에 별도 보관합니다. 실제 완료 횟수는 progress.json으로 확인하며 100회 완료 전에 통과했다고 보고하지 않습니다. PC/모바일 Chromium 검사는 별도로 실행합니다.

현재 운영 DB에 없는 인증 키를 Google Authenticator의 6자리 숫자만으로 복원할 수는 없습니다. 키가 실제로 저장되지 않은 계정은 저장 실패 수정 이후 본인 앱과 등록 확인을 완료해야 연결됩니다. 앱에서 항목 삭제도 서버에 통지되지 않으므로 자동 해제하지 않습니다.
