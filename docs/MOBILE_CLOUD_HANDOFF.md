## 아직 완료되지 않은 최신 요청 — 최우선 작업

사용자가 아래 다섯 기능을 PC·모바일 각각에 맞게 추가하고, 글 작성 영역은 모두 기존 편집기를 사용하며, 필요한 보조 기능도 만들고 마지막에 오류를 검토·수정해 완성하라고 요청했습니다.

1. 포트폴리오와 이력서 PDF 내보내기.
2. 프로젝트 설명 양식: 작업 목표, 배경, 역할과 기여도, 기간, 사용 도구, 문제 해결 과정, 결과·성과, 배운 점.
3. 마이페이지의 이력서·프로필 영역: 이름, 직무, 이메일, 연락처, 개인 링크, 풍부한 서식의 본문.
4. 지원 회사별 포트폴리오 복제: 기존 작품 구성과 설명, 소개 및 이력서 복사. 복제본의 회사·직무 및 설명을 별도로 편집.
5. 공유 화면 미리보기: 공개 링크를 만들기 전에도 실제 공유 화면을 확인. 포트폴리오와 게시글 둘 다 지원. 포트폴리오는 PC/모바일 화면 폭 선택.

현재 인계 브랜치의 변경은 **개발 중이며 main이나 실제 사이트에 배포하지 않았습니다.** 아래 구현·검토 상태를 확인해 남은 작업을 마무리하고, main에 반영한 뒤 `portfoliv` 배포 성공까지 확인하세요. 사용자에게 이미 완성된 기능처럼 말하지 마세요.

### 현재 구현된 코드

- `career-content.js`: 기존 서버의 rich text sanitizer를 재사용하는 본문·프로필 입력 검증. 프로필 항목 제한, HTTPS 개인 링크, 이메일, 본문 25,000자 및 HTML 150,000자 제한.
- `career-profile.js`: 본인 프로필 GET/PATCH, 버전 충돌 방지. 다른 사용자 프로필을 지정하는 입력 없음.
- `models/PortfolioUser.js`: `careerProfile`, `careerRevision` 추가.
- `models/PortfolioCollection.js`: `introductionHtml`, `targetCompany`, `targetRole`, `resume`, `projectNotes` 추가. 기존 데이터 기본값 및 휴지통 설정 유지.
- `portfolio-builder.js`: 추가 필드 저장, 본인 게시글만 선택, 프로젝트 설명의 postId가 선택 목록에 포함되는지 확인, 최대 200개, 본문 합계 제한. 회사별 복제 엔드포인트 `/api/portfolios/:id/duplicate`는 creationKey로 중복 방지하며 공유 토큰을 복사하지 않음.
- `sharing.js`: private `/api/portfolios/:id/preview`, `/api/posts/:id/preview`. 공개 공유 DTO와 같은 출력 구조. 원본 ownerId, 계정 정보, 내부 회사·직무 분류는 공개 출력에서 제외. 포트폴리오에 명시적으로 저장된 이력서만 출력.
- `public/js/career.js`: 기존 `window.portfolioTextEditor.mount()`로 소개글·프로필·프로젝트 설명 편집기 연결. 프로젝트 하나씩 선택해 설명 편집, 양식 삽입. 마이페이지 프로필 저장·미리보기·PDF 버튼. 프로필을 포트폴리오에 가져오기 및 포함 체크 옵션. 가져온 프로필은 스냅샷으로 저장해 기존 포트폴리오가 프로필 수정에 따라 자동으로 바뀌지 않음.
- `public/js/portfolio-presentation.js`: 개인 포트폴리오, 공유 미리보기, 공개 공유에서 함께 사용하는 renderer. 기존 게시글 본문과 첨부 자료 유지. 개인 화면의 원본 게시글 보기 링크 유지.
- PDF는 별도 외부 AI/API 없이 브라우저 시스템 인쇄의 PDF 저장을 사용하도록 현재 작성됨. A4 인쇄 CSS, 이미지와 글꼴 대기, 외부 영상은 링크, 업로드 영상은 웹에서 확인 안내. private media의 탭 인증값을 PDF 링크에 포함하지 않도록 제거. PDF에 원본 편집용 링크는 제외.
- `public/js/portfolio-builder.js`: 추가 필드, 회사별 복제, PDF 저장, 공유 미리보기, PC/모바일 미리보기 버튼과 연결.
- `public/js/sharing.js`: 공개 링크 생성 전 게시글/포트폴리오 미리보기 버튼 추가.
- `public/js/shared-presentation.js`, `public/share.html`: 공유 DTO를 같은 renderer로 표시.
- `public/css/career.css`: PC 2열 프로필, 모바일 1열, 터치 버튼, 인쇄 스타일. 저장 버튼이 편집 영역 끝에서 동작하도록 재배치.
- `public/js/mypage.js`, `public/index.html`, `public/js/main.js`: 새 탭, 편집기 접근성 레이블, 스크립트와 스타일 연결. 수정된 기존 JS의 cache query를 올림.
- `server.js`: 새 모듈 연결 및 JSON 요청 크기 4MB.

실제 MongoDB와 사용자 게시물을 수정하지 않는 메모리 모델·로컬 서버로 확인했습니다.

- `test-career.cjs` 통과: 프로필 계정 분리, rich text 정화, 입력 검증, 다른 사용자 포트폴리오/게시글 접근 차단, creationKey 중복 방지, 복제본 설명 분리, revision 충돌, private preview/public share 출력 일치, 공유 해제와 휴지통 복원.
- `test-private.cjs` 통과: 회원가입, 해시 저장, 기존 admin 게시글 연결, 계정별 데이터·미디어·휴지통 격리, 복수 복원, 25,000자, 탭 바인딩, idle 만료, logout, origin 보호, sanitizer. 기존 테스트에 Collection/Share 모델 mock이 빠져 있어 이를 추가한 후 재실행했습니다.
- 변경한 JS들의 `node --check` 통과.
- 390×844 모바일 브라우저 화면과 PC 기본 화면에서 로컬 fixtures 검토.
- 이력서 편집·저장·다시 불러오기 확인.
- 기존 포트폴리오의 풍부한 소개글, 프로젝트 설명, 이력서 데이터가 수정 폼에 유지되는지 확인.
- PC 프로젝트 설명 수정·저장, 모바일 회사별 복제·설명 수정·저장 확인.

- 수정: 프로필 가져오기 비동기 응답이 다른 포트폴리오나 저장 중 폼을 덮지 않도록 generation 검사를 추가.

### 반드시 이어서 확인할 사항

1. **PDF 실동작과 본문 유지**: 로컬 모바일 viewport의 이력서에서 글자를 선택하고 크기를 바꾼 후 `이력서 PDF 저장`을 클릭했을 때, 브라우저 자동화의 클릭이 CDP 타임아웃으로 끝났습니다. 이어서 화면을 읽으니 인쇄용 DOM은 사라졌고 편집기의 선택 텍스트가 빈 `<h2><br></h2>`로 보였습니다. 저장된 프로필은 재로드 시 정상 복원됐습니다. 앱 코드의 PDF 함수는 편집기를 직접 변경하지 않으므로 자동화/시스템 인쇄의 부작용인지 실제 버그인지 아직 규명하지 못했습니다. 이 현상을 재현·조사하고 내용이 소실되지 않게 수정한 후 PDF를 확인하세요. 시스템 인쇄의 실제 파일 저장은 아직 완료 확인하지 못했습니다.
2. 새 포트폴리오 만들기, 양식 삽입, 여러 프로젝트 설명 전환과 순서/선택 변경 후 내용 보존, 프로필 가져오기 및 제외 상태를 더 검토하세요.
3. `public/js/career.js`가 기존 스크립트보다 뒤에서 로드됩니다. 직접 hash 접속·새로고침·로그인 상태 이벤트의 순서 경쟁을 검토하세요. 현재 테스트에서는 직접 `#mypage/resume`, 포트폴리오 `/edit` 재로드가 동작했습니다.
4. 공유 모달의 새 미리보기, 공공 DTO의 미디어 URL, 원래 공유 링크의 호환성을 확인하세요.
5. 긴 글/사진의 PDF 페이지 나눔, 실제 모바일 시스템 인쇄 지원과 안내를 확인하세요. 단순히 CSS나 준비 코드가 있다는 이유로 PDF 완성이라 보고하지 마세요.
6. 이전 클라이언트가 추가 career 필드를 보내지 않고 기존 포트폴리오를 수정하는 상황에서 새 필드가 지워지지 않는지 검토하세요. 현재 입력 함수는 생략된 추가 필드를 기본값으로 설정합니다.
7. 계정 전환/로그아웃 시 프로필·복제 폼·미리보기·인쇄용 DOM·비동기 응답의 정리 및 본인 계정 기준을 계속 유지하세요.
8. 완료 후 실제 GitHub main 반영 → Render `portfoliv`의 최신 커밋 배포 성공 및 페이지 로드를 확인하세요. 삭제한 기존 서비스를 다시 만들거나 설정하지 마세요.

## 기존에 완료·배포한 기능과 반드시 보존할 사용자 요구

### 사이트 기본과 게시글

- 기존 SNS/온라인 채팅 기능을 제거하고 포트폴리오 중심으로 전면 정리.
- 깔끔하고 세련된 디자인, PC와 스마트폰에 맞는 레이아웃.
- 사진·동영상·기타 파일을 글과 함께 하나의 게시글로 작성·업로드·열람. 본문의 원하는 위치에 첨부.
- 메인에서 별도 `게시글 등록하기`를 통해 작성 화면으로 진입. 게시글 제목/본문을 눌러 상세 화면에 진입.
- 상세의 커진 본문 화면에서 그대로 편집. 기존 rich text 편집기의 글꼴, 숫자 글자 크기, 굵기(보통과 볼드 등 300~900), 색상, 정렬, 소제목, 목록 유지.
- 글자 크기 숫자 동기화, 모바일 선택 범위가 서식 조절 중 풀리지 않도록 구현되어 있음.
- 글자 수 5,000자에서 25,000자로 확대, HTML 150,000자. 업로드 한 번 10개, 파일당 50MB.
- 새로고침 시 게시글이 2~3개로 복사되는 문제 대응: creationKey와 중복 방지. 상세/편집 hash 경로는 새로고침해도 같은 화면으로 유지.
- 처음 주소로 접속하면 홈 경로이며 인증되지 않은 사용자는 로그인 화면. 로그인·기능의 새로고침에서 강제로 홈으로 나가지 않게 유지.
- YouTube/Vimeo 외부 영상 링크 지원. 게시글 메인 표지를 눌러 영상 재생, 제목·내용을 눌러 본문 열기 분리.
- 여러 개 게시글을 메인 아카이브 카드로 표시.

### 계정과 보안

- 각각의 사용자가 아이디/비밀번호/비밀번호 확인으로 가입하고 로그인.
- 일반 사용자는 본인의 게시글·첨부 자료·포트폴리오·휴지통만 접근 가능. 관리자라고 다른 회원 개인 자료를 보는 기능을 추가하지 마세요.
- 관리자 별도 로그인, 기존 Render 관리자 비밀번호 사용. 관리자 내부 아이디 `__archive_admin__`.
- 비밀번호는 해시 저장. 기존 비밀번호 원문을 마이페이지에서 복원·표시하는 기능은 구현하지 않았고 사용자에게 불가능한 이유를 설명함.
- 로그인·회원가입·관리자 로그인·계정 변경의 입력 비밀번호는 감은 눈/뜬 눈 아이콘으로 숨김·표시를 전환.
- HttpOnly/SameSite Strict session cookie, 일반 로그인은 sessionStorage의 탭 토큰으로 탭 종료 후 재로그인.
- 로그인 유지 체크 시 브라우저 사용 중 유지하고 30분간 활동이 없으면 자동 로그아웃. 기기 재부팅을 웹에서 확실히 감지할 수 없어 이 대안에 사용자가 동의함.
- 마이페이지 내 정보/계정 정보. 회원의 아이디와 비밀번호 변경은 가입일 기준 14일마다 총 2회, 누적 없이 초기화. 현재 비밀번호 확인, 계정 변경 후 다른 session 무효화.

### 공지사항·뉴스·관리자

## 작업 방식과 소통

- 한국어로 초보자도 이해하기 쉽게 설명하고, 진행 상황을 간결하게 알려주세요.
- 사용자는 반복 확인 요청에 매우 불편함을 느낍니다. 이미 승인한 구현·배포·검토는 계속 진행하세요. 영구 삭제 등 실제 정책상 마지막 확인이 필요한 때만 정확한 이유와 대상 설명.
- 사용자가 작업 중 질문하면 짧게 답하고 기존 작업을 계속하세요. 마지막 세 질문은 모바일 ChatGPT 연결, 이 PC의 Codex 연결, PC가 꺼져도 클라우드 작업을 계속하도록 전달하는 방법이었습니다.
- 현재 채팅 자체의 클라우드 이동은 지원되지 않음을 안내했고, 연결한 PC가 꺼지면 Remote도 중단됨을 설명했습니다. 이 인계는 별도 클라우드 작업에서 이어가기 위한 것입니다.
- API 호출/AI 자동 생성 비용을 원하지 않으며 AI API 연결은 하지 말라고 명시했습니다.
- 사이트를 앱으로 만들 수 있는지 질문만 했고 앱 제작은 시작하지 않았습니다.
- 최종 완료 보고는 기능 위치·사용 방법·검토 범위·남은 제한을 정확히 구분하세요. 모든 기기에서 오류가 절대 없다는 보장은 하지 마세요.
