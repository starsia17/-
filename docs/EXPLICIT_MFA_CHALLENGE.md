# 명시적 2단계 로그인 — 2026-10-12

사용자는 Google Authenticator 등록 확인 및 복구 코드 발급까지 완료한 계정에서 비밀번호만으로 로그인된다고 재차 보고했습니다. 시험 결과만으로 운영 계정 문제 해결을 단정하지 않습니다. 실제 계정의 DB 상태를 직접 읽을 인증은 현재 제공되지 않습니다.

등록 계정은 첫 로그인 요청에서 비밀번호 확인 후 HTTP 401과 mfaRequired, 5분 유효한 무작위 challenge를 받습니다. 이 단계에서는 6자리 코드를 함께 보내도 세션이 발급되지 않습니다. challenge는 서버 메모리에서 계정 ID, 계정 버전, 탭 토큰과 연결되며 최대 10,000개로 제한합니다. 만료 항목은 새 challenge 발급 시 정리합니다. 서버 재시작 시에는 비밀번호 확인부터 다시 시작해야 합니다.

두 번째 요청은 같은 계정·탭·버전의 challenge와 정확한 인증 코드 또는 미사용 복구 코드가 있어야 합니다. 클라이언트는 첫 단계에서 자동완성된 코드를 전송하지 않고 서버가 요구한 뒤 코드 확인 버튼을 표시합니다. 등록되지 않은 계정은 원래 비밀번호 로그인을 유지합니다.

IP 제한은 비밀번호 단계와 서버가 발급한 유효한 challenge의 인증 단계에 각각 기존 30회 한도를 적용합니다. 임의 challenge는 비밀번호 단계의 제한을 공유합니다. 인증 코드는 별도로 계정별 반복 추측 제한과 원자적 소비를 유지합니다. 이전 세션 폐기, 세션 발급 직전 계정 재검사, 등록 계정의 구형 세션 거절도 유지합니다.

등록 여부는 mfaEnabled, 저장된 암호화 키, 남아 있는 복구 코드 해시 중 하나라도 있으면 필수 인증으로 판단합니다. 키가 없어도 복구 코드 등록 흔적이 있으면 비밀번호만으로 진행하지 않고 실패합니다. 복구 코드 해시나 인증 키는 공개 응답에 포함하지 않습니다.

HTTP 테스트는 인증 코드를 첫 요청에 포함해도 401·빈 쿠키·사용자 세션 미발급인지 확인하고, 이어서 실제 challenge와 코드를 검증합니다. 회원·관리자, 등록·미등록, 코드 재사용·예전 세션·기존 개인 데이터 격리와 career 기능 검사가 통과했습니다. 실제 Chromium의 PC 1440px와 모바일 390px에서 QR 등록 완료, 2단계 로그인, 로그아웃, 인증 코드 누락 차단, 복구 로그인, 해제를 검사했습니다. 운영 계정의 비밀번호를 입력하거나 데이터/등록 상태를 수정하지 않았습니다.
