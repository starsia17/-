# 포트폴리브 1.0.0 — 취업 준비 기능

운영 주소: https://portfoliv.onrender.com/

## 사용 방법

1. **이력서·프로필**: 마이페이지 → 이력서·프로필에서 이름, 직무, 이메일, 연락처, HTTPS 개인 링크와 본문을 작성합니다. 기존 게시글 편집기의 서체·크기·색상·문단 도구를 사용합니다. 프로필은 본인에게만 보이며 포트폴리오에 명시적으로 포함했을 때만 함께 공유됩니다.
2. **프로젝트 설명**: 내 포트폴리오 → 새로 만들기 또는 구성 수정 → 프로젝트 설명에서 선택한 작업별로 작성합니다. 양식은 목표·배경, 역할·기여도, 기간·도구, 문제 해결, 성과, 배운 점을 제공합니다. 기존 글에 양식을 넣으면 교체 확인이 표시됩니다.
3. **프로필 포함**: 포트폴리오 구성의 이력서 포함을 켠 뒤 마이페이지 프로필을 가져오거나 직접 작성합니다. 가져온 내용은 저장 시 복사본이 됩니다. 마이페이지 수정이 기존 포트폴리오의 프로필을 바꾸지 않습니다. 포함을 끄면 연락처와 이력서를 출력·공유에서 제외합니다.
4. **회사별 복제**: 목록 또는 포트폴리오 화면의 회사별 복제로 새 구성 수정 화면을 엽니다. 회사·직무는 본인 목록에서 분류할 때만 보입니다. 소개, 이력서, 추가 프로젝트 설명은 독립적으로 수정합니다. 원본 게시글은 계속 참조하므로 원본 작품·게시글 수정은 원본과 복제본 모두에 반영됩니다. 공유 링크는 복사하지 않습니다.
5. **공유 전 미리보기**: 포트폴리오의 공유 화면 미리보기 또는 게시글·포트폴리오의 공유하기 창에서 확인합니다. 공개 동의 없이 미리보기만 할 수 있고, 포트폴리오는 PC·모바일 폭을 선택할 수 있습니다. 실제 링크 생성은 별도의 공개 동의와 버튼을 사용합니다.
6. **PDF**: 포트폴리오의 PDF 저장 또는 마이페이지의 이력서 PDF 저장을 누르면 독립적인 인쇄 화면이 열립니다. PC는 시스템 인쇄에서 PDF 저장을 선택합니다. 모바일은 새 화면의 PDF 저장·인쇄를 누릅니다. iPhone·iPad는 인쇄 미리보기를 확대한 뒤 공유 메뉴를 통해 파일로 저장할 수 있습니다. 앱 내 브라우저에서 인쇄를 지원하지 않으면 Safari·Chrome을 사용합니다. 팝업 차단 시 허용 후 다시 누릅니다.

PDF는 A4이며 작성 중인 본문을 포함할 수 있지만 자동으로 서버에 저장하지는 않습니다. 인쇄를 취소해도 원래 편집 내용은 유지됩니다. 영상은 재생되지 않고 외부 링크 또는 웹에서 확인 안내로 바뀝니다. 비공개 첨부 다운로드 주소와 편집용 원본 링크는 PDF 링크에서 제외합니다. 이미지 로딩 실패는 인쇄 화면에 안내됩니다.

## 저장·접근 검토

- 추가 필드를 보내지 않는 구형 포트폴리오 클라이언트는 기존 소개 서식, 회사·직무, 이력서와 선택 작업의 설명을 보존합니다. 명시적인 빈 값으로만 지웁니다. 선택 해제한 작업의 설명은 저장 구성에서 제외합니다.
- 저장 버전 충돌은 409 응답으로 알립니다. 프로필과 포트폴리오의 내용·길이·소유권을 서버에서 검사합니다.
- 프로필 가져오기 중에는 해당 입력을 잠급니다. 다른 구성으로 이동하거나 저장·로그아웃·계정 전환한 뒤 도착한 응답은 적용하지 않습니다.
- 마이페이지 탭 전환과 같은 계정의 로그인 상태 확인은 작성 중인 프로필을 초기화하지 않습니다. 계정 전환·로그아웃은 프로필·회사·설명·공유 미리보기·인쇄 문서를 정리합니다.
- 기존 사용자별 게시글, 미디어, 휴지통, 관리자·뉴스·공지 기능을 유지합니다. AI API를 사용하지 않습니다. 운영 DB나 환경변수 값을 코드에 넣지 않습니다.

## 재현 가능한 검증

```sh
npm install
node test-private.cjs
node test-career.cjs
```

PC·모바일 브라우저 검증은 Playwright가 설치된 개발 환경에서 메모리 fixture만 사용합니다. 운영 데이터베이스를 연결하지 마세요.

```sh
node test-career.cjs --serve
# 별도 터미널. Playwright와 Chromium을 준비한 개발 환경에서 실행합니다.
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium node test-career-browser.cjs
```

브라우저 검증은 1440×1000, 390×844 Chromium에서 프로필·편집 내용 보존, PDF 파일 생성, 새 구성, 다중 프로젝트 설명·양식·선택·순서, 프로필 가져오기·제외, 회사별 복제, 게시글·포트폴리오 미리보기, 공개 미디어, 새로고침, 늦은 응답과 계정 전환을 다룹니다. PDF·화면 파일은 기본 `/tmp/portfoliv-browser-checks`에 저장됩니다. 실제 iOS·Android 기기의 시스템 인쇄 UI 및 Safari 동작은 별도 기기 검증이 필요합니다.

## 배포 확인

Render의 기존 `portfoliv` 서비스는 GitHub main을 자동 배포합니다. `/api/health`는 DB 연결 상태, 버전, Render의 `RENDER_GIT_COMMIT`을 반환합니다. 배포 성공은 코드 반영만으로 판단하지 않고 운영 응답의 commit이 해당 main 커밋과 일치하며 DB가 connected인지 확인합니다. 이전 Render 서비스는 사용하지 않습니다.

원래 인계 시점의 전체 요구사항은 [MOBILE_CLOUD_HANDOFF.md](MOBILE_CLOUD_HANDOFF.md)에 보존되어 있습니다.
